# Jenkins + Node.js practical demo

This app shows a web page at `/` and returns `{"status":"ok"}` at `/health`.
The focus is the Jenkins automation: after one-time setup, pushing code to your
configured Git branch automatically tests, builds, and deploys the app.

## Files

```text
jenkins-demo/
├── src/app.js          # HTTP routes and the message you can change
├── src/server.js       # Starts the server on port 3000
├── tests/app.test.js   # HTTP tests using Node's built-in test runner
├── scripts/build.js   # Copies source to dist for deployment
├── eslint.config.js   # Code quality rules
├── Jenkinsfile        # Automated pipeline
├── Dockerfile         # Runs the built app independently of Jenkins
├── .dockerignore
├── .gitignore
├── package.json
└── package-lock.json  # Exact dependency versions for npm ci
```

`node_modules/` is generated by `npm ci`; `dist/` is generated by `npm run build`.
Both are excluded from Git. This app has no runtime npm dependencies; ESLint is
a development dependency.

## Try locally

Install Node.js 22 or newer, then run from this folder:

```bash
npm ci
npm run lint
npm test
npm run build
npm start
```

Open http://localhost:3000. Press Ctrl+C to stop. For local development, use
`npm run dev`, which restarts on source changes.

## One-time Jenkins setup

1. Push the project to a Git repository such as GitHub. Commit the lockfile too.
2. Have a running Jenkins installation with **Pipeline** and **Git** plugins.
3. In **Manage Jenkins → Nodes**, configure one persistent Linux agent with
   the label **node-docker-demo**. It needs Git, Node.js 22+, npm, and a running
   Docker Engine with its CLI. The user running the agent must be able to run
   `docker info` successfully. Docker access grants powerful host privileges;
   use a dedicated learning machine and a trusted repository.
4. Create **New Item → Pipeline**. Under **Pipeline**, choose **Pipeline script
   from SCM**, select **Git**, enter your repository URL and credentials if
   private, and set **Branch Specifier** to `*/main` (or your actual branch).
5. Set **Script Path** to `jenkins-demo/Jenkinsfile` if you push the parent
   `devops_prac` folder. Use `Jenkinsfile` if this folder itself is the repository
   root. The pipeline detects both app locations.
6. Save and click **Build Now** once. This first run registers the polling
   trigger in the Jenkinsfile and deploys the initial app.
7. Open `http://<agent-host>:3000`. For an agent on your own machine, use
   `http://localhost:3000`. For a remote agent, allow inbound TCP port 3000 as
   needed. Jenkins commonly uses port 8080; the app uses port 3000.

If Jenkins itself runs in a container, installing Docker on your laptop alone
does not configure its agent. Use a persistent Linux agent with the above tools
and Docker access. The app is deployed on the Docker host used by that agent.
Reserve this label, container name, and port for this single demo job.

## What runs automatically?

```text
You edit, commit, and push to main
                 ↓
Jenkins polls Git every minute and detects the new commit
                 ↓
Checkout → Install → Lint → Test → Build → Package → Deploy → Verify
```

| Step | What Jenkins does |
| --- | --- |
| Checkout | Automatically checks out the configured Git branch into its workspace |
| Install | Runs `npm ci` using the committed lockfile |
| Lint | Runs ESLint to catch code issues |
| Test | Sends HTTP requests to a temporary app and checks the responses |
| Build | Copies plain JavaScript to `dist/`; no compiler is needed |
| Package | Builds a Docker image tagged with the Jenkins build number |
| Deploy | Replaces the previous demo container with the new image |
| Verify | Waits for the container health check to pass; otherwise fails the build |

Later stages are skipped when an earlier stage fails. A lint, test, build, or
image-build failure leaves the existing deployed container running. Container
replacement has brief downtime; a failure during deployment or health checking
does not automatically restore the previous version. This is a single-host
learning example, with no production rollout or automatic rollback.

The detached Docker container keeps running after the Jenkins job finishes.
Its restart policy restarts it after Docker/host restarts unless explicitly stopped.
No manual start or deploy command is needed after each push. Jenkins and its
agent must remain available to process changes.

## Demonstrate automation

1. Edit the `message` string in `src/app.js` (keep the word `Jenkins` so the
   homepage test continues to pass).
2. Commit and push:

   ```bash
   git add src/app.js
   git commit -m "Update demo homepage message"
   git push
   ```

   Run these commands inside `jenkins-demo`.
3. Wait about a minute plus build time. A new build appears without clicking
   **Build Now**. Open its **Console Output** to follow each stage.
4. Refresh the app page to see the updated message.
5. To see the quality gate, change the health test's expected status from `ok`
   to `broken`, commit, and push. The **Test** stage fails and deployment is
   skipped. Restore the expectation and push to get a successful build again.

Polling needs no public URL, so it works well for a local Jenkins demo. For
immediate GitHub notifications instead, configure the Jenkins GitHub plugin,
enable **GitHub hook trigger for GITScm polling** in the job, and add a GitHub
push webhook targeting `https://<your-jenkins>/github-webhook/`. GitHub must be
able to reach that URL; localhost is not reachable from GitHub. Polling already
provides automatic execution, so a webhook is optional.

## Docker commands (optional local practice)

After `npm run build`, with Docker installed:

```bash
docker build -t jenkins-node-demo:local .
docker run -d --name jenkins-node-demo-local -p 3001:3000 jenkins-node-demo:local
docker logs jenkins-node-demo-local
docker rm -f jenkins-node-demo-local
```

The local practice container uses http://localhost:3001 to avoid the pipeline's
port 3000. To stop the Jenkins deployment, run `docker rm -f jenkins-node-demo`
on its Docker host. Disable the Jenkins job to prevent later pushes redeploying.
Build images remain on that host for inspection; periodically remove old demo
images you no longer need.

## Common problems

- **Waiting for next available executor:** check the agent is online and has the
  exact `node-docker-demo` label.
- **npm/node/docker not found:** install the missing tool on the agent and make
  it available in the Jenkins user's PATH.
- **Docker permission denied:** verify Docker access as the agent's OS user.
- **Port already allocated:** stop the conflicting service or change `APP_PORT`
  in the Jenkinsfile and use that port in your browser.
- **No automatic build:** run the job once, confirm the configured branch was
  pushed, and inspect the job's **Git Polling Log** and repository credentials.
